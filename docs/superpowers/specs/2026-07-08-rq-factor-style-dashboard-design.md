# 米筐官方因子收益率投资者风格看板设计

## 背景

当前 notebook `因子回测/learn/米筐官方因子收益率_风格趋势.ipynb` 已经能通过米筐 `rq.get_factor_return()` 获取 v1/v2 风险因子收益率，并画出累计收益曲线、因子大类聚合、行业因子和自建 Barra 对照。

这套处理适合作为因子收益复现和研究验证，但用户的实际使用场景是投资者视角的市场风格观察：每天或每周快速判断 A 股市场当前在奖励什么风格、惩罚什么风格，以及风格是否正在切换。因此 notebook 需要从“复现研究图”改造成“风格雷达看板”。

## 目标

改造后的 notebook 应优先回答四个投资问题：

1. 当前市场最强和最弱的显式风格因子是什么。
2. 因子收益为正或为负分别代表哪类股票跑赢。
3. 20 日、60 日、120 日和年初至今的风格信号是否一致。
4. 市场风格是否出现切换迹象，例如动量转弱、大小盘反转、高波动重新占优、价值成长切换。

## 非目标

本次不重写米筐数据拉取接口，不重新实现 Barra 截面回归，不改动自建 Barra 学习 notebook，也不把本 notebook 变成完整实盘择时系统。

自建 Barra 对照、v1/v2 对比和行业因子轮动可以继续保留，但应放到研究附录或次要章节，不作为投资者主视图。

## 推荐方案

采用“投资者看板版”方案：

- 主分析模型使用米筐 v2。
- 主分析对象只包含显式风格因子，排除 `comovement` 和行业因子。
- `comovement` 单独作为市场整体温度计。
- 行业因子单独作为行业轮动视角。
- 大类聚合只做辅助摘要，不作为风格判断主依据。

## 因子方向解释层

新增一个统一的 `FACTOR_DIRECTION_MAP`，用于解释每个因子的正负收益含义。因子收益率的投资者解释口径为：

> 因子收益为正，表示高暴露方向跑赢低暴露方向；因子收益为负，表示低暴露方向跑赢高暴露方向。

初始方向字典：

| 因子 | 正收益代表 | 负收益代表 |
| --- | --- | --- |
| `momentum` | 过去强势股继续跑赢 | 弱势股或反转方向占优 |
| `longterm_reversal` | 长期反转暴露占优 | 长期趋势延续方向占优 |
| `size` | 大市值暴露占优 | 小市值暴露占优 |
| `mid_cap` | 中市值暴露占优 | 非中市值暴露占优 |
| `beta` | 高 beta、高弹性股票跑赢 | 低 beta、防御股票跑赢 |
| `residual_volatility` | 高特质波动股票跑赢 | 低波动股票跑赢 |
| `liquidity` | 高换手、高交易活跃度股票跑赢 | 低换手、低交易活跃度股票跑赢 |
| `book_to_price` | 高账面市值比、低估值股票跑赢 | 低账面市值比、高估值股票跑赢 |
| `earnings_yield` | 高盈利收益股票跑赢 | 低盈利收益股票跑赢 |
| `dividend_yield` | 高股息股票跑赢 | 低股息股票跑赢 |
| `growth` | 成长暴露占优 | 非成长或稳态暴露占优 |
| `profitability` | 高盈利能力股票跑赢 | 低盈利能力或投机方向跑赢 |
| `earnings_quality` | 高盈利质量股票跑赢 | 低盈利质量股票跑赢 |
| `investment_quality` | 高投资质量股票跑赢 | 低投资质量股票跑赢 |
| `earnings_variability` | 高盈利波动暴露占优 | 盈利更稳定方向占优 |
| `leverage` | 高杠杆股票跑赢 | 低杠杆股票跑赢 |

方向字典应同时用于表格、图标题、自动结论和注释，避免同一因子在不同位置出现解释不一致。

## Notebook 结构

### Part 0：环境和参数

保留当前环境初始化、字体设置、米筐初始化和时间窗口参数。新增投资者看板参数：

- `STYLE_WINDOWS = [20, 60, 120]`
- `PRIMARY_MODEL = "v2"`
- `PRIMARY_STYLE_FACTORS`，从 v2 风格因子中排除 `comovement`
- `DASHBOARD_LOOKBACK_FOR_RANK = 60`

### Part 1：数据加载

保留现有 `load_factor_return_with_cache()`，继续复用缓存 parquet 和 meta 文件。

新增加载后校验：

- v2 数据为空时给出明确错误。
- 目标风格因子缺失时打印缺失列表。
- 最新日期滞后当前交易日过多时给出提醒，但不阻断 notebook 运行。

### Part 2：因子方向说明表

新增 `build_factor_direction_table(style_factors)`，输出每个因子的：

- 因子英文名
- 中文名称
- 所属风格组
- 正收益含义
- 负收益含义
- 当前累计收益方向

这个表放在所有图之前，让读者先拿到解释口径。

### Part 3：风格表现总览表

新增 `build_style_performance_table(fr, style_factors, windows)`。

输出列：

- `20日收益%`
- `60日收益%`
- `120日收益%`
- `年初至今收益%`
- `最新5日收益%`
- `当前方向`
- `投资者解读`
- `信号强度`

计算口径：

- 窗口收益使用 `(1 + factor_return).tail(window).prod() - 1`
- 年初至今收益使用当前缓存窗口内累计收益，若后续需要严格自然年口径，再增加 `YTD_START`
- 信号强度按 60 日收益绝对值分档，例如强、中、弱、噪音

表格默认按 60 日收益排序，因为 60 日更适合观察中短期风格，而 20 日容易太噪，120 日可能反应较慢。

### Part 4：核心图表

保留少量高信号图，减少线条噪音。

1. 风格雷达热力图
   - 行为显式风格因子。
   - 列为 20 日、60 日、120 日、年初至今。
   - 使用红绿或蓝红发散色表示正负收益。
   - 每个格子标注百分比。

2. 当前风格强弱柱状图
   - 默认展示 60 日收益排序。
   - 标题明确说明“正值=高暴露方向跑赢，负值=低暴露方向跑赢”。
   - y 轴标签可使用中文短名，减少英文因子名阅读成本。

3. 关键风格对照图
   - 大小盘：`size`、`mid_cap`
   - 动量/反转：`momentum`、`longterm_reversal`
   - 风险偏好：`beta`、`residual_volatility`
   - 价值/成长/股息：`book_to_price`、`earnings_yield`、`dividend_yield`、`growth`
   - 质量：`profitability`、`earnings_quality`、`investment_quality`

4. 市场温度背景图
   - 单独画 `comovement` 或中证全指累计收益。
   - 不把它放入风格排名。

### Part 5：自动生成市场风格结论

新增 `generate_market_style_commentary(perf_table)`。

输出内容包括：

- 当前最强的 3 个因子及其投资者含义。
- 当前最弱的 3 个因子及其投资者含义。
- 关键组合判断：
  - 动量是否占优。
  - 大盘还是小盘占优。
  - 高 beta 和高波动是否同向。
  - 价值、成长、股息谁更强。
  - 质量因子是否被奖励。
- 风险提醒：
  - 若 20 日和 120 日方向相反，提示可能处于切换期。
  - 若 60 日强度极端但最新 5 日反向，提示短期反转风险。

示例输出：

> 当前市场风格：动量占优，高 beta 占优，低波动占优，高换手受惩罚。整体更像“趋势延续 + 低波保护并存”的行情，而不是单纯高风险偏好行情。

### Part 6：研究附录

把原 notebook 中偏研究的内容移到后面：

- v1/v2 对比。
- 自建 Barra 对照。
- 因子大类聚合。
- 行业因子趋势。
- 滚动窗口细节。

这些内容保留，但标题明确标为“研究附录”，避免干扰主看板。

## 数据流

```text
米筐 get_factor_return 或本地缓存
  -> fr_v2
  -> 过滤显式风格因子
  -> 因子方向字典
  -> 多窗口收益表
  -> 热力图 / 排名图 / 对照图
  -> 自动中文结论
  -> comovement 与行业因子作为背景或附录
```

## 错误处理

- 如果米筐 API 不可用，继续使用已有缓存，并在 notebook 输出中提示数据最新日期。
- 如果缓存和 API 都不可用，抛出清晰异常，提示检查米筐权限或网络。
- 如果部分因子缺失，不应静默忽略，应在方向表前提示缺失因子。
- 如果样本长度不足 120 日，120 日列显示为 `NaN` 或“样本不足”，不强行年化。

## 验证方式

实现后做三类最小验证：

1. 用 `E:\working\anaconda3\envs\quant\python.exe` 读取 notebook，确认 JSON 格式合法。
2. 执行新增的纯计算函数，对本地 `saved_data/rq_factor_return_v2.parquet` 生成表现表，确认列名、排序和百分比结果正确。
3. 如果环境支持，运行 notebook 中新增核心 cells 或用 `nbconvert --execute` 执行到看板部分；若米筐权限或网络限制导致无法执行 API，则使用缓存验证。
